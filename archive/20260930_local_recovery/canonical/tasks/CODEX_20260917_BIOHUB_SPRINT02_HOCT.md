## 2. 唯一候选 H1 的数学定义

对每个视频，取得 G1 所有后处理完成、最终配置确定后的同一份基准图 `(V, E)`。节点身份必须包含视频、帧和原节点 ID。

定义：

- `P`：G1 基准图中每个分裂母节点的全部出边。按基准图的出度确定并冻结，不能在删边过程中重新计算。异常多出边节点也先整体保护并报告，不擅自修图。
- `C`：能够证明已经进入 HOCT 本次实际候选图、完成有效模型推断及完整求解，而且端点映射可靠的 G1 普通边集合。`C ⊆ E \ P`。
- `S`：同一次 HOCT 成功求解后，被选中的边，映射回 G1 原始节点身份。
- `D = C \ S`。
- **H1：`V_H1 = V`，`E_H1 = E \ D`。**

必须同时满足：`P ⊆ E_H1 ⊆ E`。不新增边、不新增或删除节点、不改变坐标、不改检测器、不改 G1 分类器的 0.95 门槛、不改几何门、距离排序、cap 或原自动选择器。不得在 H1 之后再跑短轨迹剪枝、补洞、重连或平滑，否则会引入第二项改动。

保护分裂出边不等于保证官方分裂指标一定不变：最终图仍必须重新评分，不能以结构断言代替评分结果。

### 未覆盖不等于否定

只有可靠属于 `C` 的边才可能删除。下列情况保留 G1 边并分别计数：

- 端点映射失败、标签球重叠造成对象丢失、坐标／单位无法核对。
- HOCT 的候选距离、邻居数、时间跨度或分块范围没有覆盖该边。
- 图像／特征缺失、推断异常、求解未完成、超时或预算不足。

不得通过“距离够近”推断一条边已被模型评价；不得把整张 G1 图减去 HOCT 输出当成可删集合。优先利用固定版本实际支持的候选图返回／导出或最小观测接口。若无法获得可靠的候选覆盖证据，标记 `BLOCKED_HOCT_COVERAGE_UNOBSERVABLE`，不能降低定义后继续提交。

HOCT 的分块／窗口结果只有在按源实现完成合并且能证明覆盖时才可用于删除。未完成或部分可行求解结果不作为否定证据。

通过 Stage C 后实际发出本轮唯一 submission，提交描述包含任务 ID、H1、准确 V／SV。提交前先只读核对同任务是否已提交，避免会话中断后的重复写入。绑定比赛、账号、submission ID、Notebook、版本、SV、时间和最终候选哈希。

使用现有官方详情与提交列表尽量交叉核对；记录实际可读范围和原始小型回执。排行榜队伍分、Notebook 卡片 Best Score、局部分数均不得替代该 submission 的正式分数。

首次观察最长 60 分钟，仅对同一 submission 做有限频率只读查询。未出现终态就保存 `SCORE_PENDING`、最后读取时间和精确 ID 后停止本次观察，不重提、不创建自动任务、不声称评分完成。续做本任务时先读已有账本，只继续已有 submission 的只读回收。

终态决定：

| 平台结果 | 决定 |
|---|---|
| COMPLETE，Public > 0.948 | `PUBLIC_UP`，报告精确差值，可推荐 H1 作为后续比较基准 |
| COMPLETE，Public >= 0.950 | 在 `PUBLIC_UP` 基础上标记 `TARGET_PUBLIC_REACHED` |
| COMPLETE，Public = 0.948 | `HOLD_G1`：未观察到提分，不晋升 H1 |
| COMPLETE，Public < 0.948 | `REJECT_H1`：保留 G1 |
| ERROR／无正式分 | `PLATFORM_ERROR`：记录可见错误，不写成方案低分 |
| 未取得终态 | `SCORE_PENDING`：方法效果仍待正式证据 |

同时可列相对 Forge 0.947 的历史差值，但主比较必须为相对 G1 0.948。任何结果都不自动修改最终选择，不启动第二候选。一次 Public 提升不等于 Private／稳定泛化保证，隐藏实际覆盖和配置不可读时仍写 UNKNOWN。

## 8. 交付与验收：少量文件，完整证据

目录固定为 `experiments/BIOHUB_SPRINT02_HOCT_20260917/`。至少保存：

- `contract.json`：任务哈希、固定来源、样本与模型配置、预算、事前门槛。
- `manifest.json`：实际读取范围、输入／权重／源码／评分器哈希、训练谱系限制、环境及模型选择；可引用旧证据，不复制大文件。
- `hoct_guard.py`、必要的构建／运行适配及测试代码；`diagnostic/`、`production/` 下保存实际生成的 Notebook／metadata／精确差异。未进入的阶段不要制造伪产物。
- `request_ledger.jsonl`：所有写请求意图、实际发送、响应、已用额度及精确平台对象；续跑共用账本。
- `diagnostic_metrics.json`、小型逐视野／删边归属与覆盖汇总。
- `runtime_receipt.json`、`formal_receipt.json`、`verification.json`：只填写实际取得内容；未执行用 null／NOT_RUN。
- `reports/20260917_BIOHUB_SPRINT02_HOCT_RESULTS.md`：人类可读结论、实际修改、对照和分数、执行覆盖、失败／未知、资源消耗、下一步是否应停止。

完整图、原始影像、模型、CSV 和大日志放现有忽略目录或合规的 Kaggle 私有输出；GitHub 只收代码与小型证据，不写入签名 URL、Token、Cookie。

验收分开报告：

1. `execution_status`：实际达到的阶段、合法停止原因或评分终态。
2. `result_status`：NO_EFFECT／EXPLORATORY／PUBLIC_UP／HOLD_G1／REJECT_H1／UNKNOWN。
3. `delivery_status`：本批文件是否完成远端核验。合法停止可以交付已核验证据，但不得写成未运行阶段已完成。

复用现有验收器，补上本任务的预算、不变量、真实执行与版本绑定检查。自测不冒称第三方独立验收。不以“报告文件存在”证明推断、提交或评分完成。

推送本任务分支后，固定内容 commit，实际从 GitHub 回读本批应交付文件的完整字节并核对 SHA256，报告真实匹配数、工作分支 HEAD、remote HEAD、ahead／behind 和该 worktree 状态。保存回读回执时区分“已核验内容 commit”与之后保存回执的收尾 commit，避免要求文件包含自己的最终哈希；收尾新增文件仍须实际回读核对。

main 不由本任务修改；如他人同时更新 main，记录远端变化，不回退他人提交。不得把其他 worktree 的未提交改动误报为本任务污染，也不得为了全局洁净删除用户文件。

最终回复只需明确：H1 到了哪一步、正式精确得分或为何没有分、是否真执行了 HOCT、删了多少普通边和回退了多少视频、相对 G1 的结果、预算消耗，以及固定 GitHub 报告链接和核验结果。不要用调研篇幅代替实测结果。
