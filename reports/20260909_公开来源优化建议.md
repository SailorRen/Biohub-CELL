## 最值得先处理的两处结构问题

**1．B0 手写分裂 proxy 不等价于官方当前公开评分实现。**

`SOURCE_CODE_VERIFIED`：B0 cell8 使用一次全图节点匹配、弱连通组件和任意深度女儿后代判断分裂。官方固定提交 `075fc5f5a52d11077f9dc2b074644618f26939e2` 使用每个分裂局部匹配、有向双分支约束、预测 fork 与真实事件的一对一匹配，并补充合流、跨组件等 FP 处理。这是具体实现差异，不是笼统猜测“CV 不准”。[官方 division 源码](https://github.com/royerlab/kaggle-cell-tracking-competition/blob/075fc5f5a52d11077f9dc2b074644618f26939e2/src/tracking_cellmot/division_metrics.py#L227)

B0 已包含节点总量修正，不能说它漏掉数量惩罚。复算官方指标应使用 `per_sample_metrics → summarise` 的完整入口；同仓 `evaluate_datasets` 便捷入口并不包含全部数量修正。本轮未发现官方存在最小连通组件大小过滤；min-track-length=6 是 B0 自己的后处理。[官方聚合与入口](https://github.com/royerlab/kaggle-cell-tracking-competition/blob/075fc5f5a52d11077f9dc2b074644618f26939e2/scripts/evaluate.py#L67)

下一步建议在相同小批已存在预测上做官方与手写评分对照，拆出 edge Jaccard、数量乘子和分裂事件，观察自动 PP 排名是否改变。有预测可复用时不必重新运行模型；若没有保留相同预测，就如实记缺口。本轮只核实静态不等价，**尚未实测差值，不知道它会否改变 tight55/relaxed9 选择，更不能据此否定正式 0.946 或解释 C1 下降**。官方公开代码也不等于已验证 Kaggle 私有部署逐字相同。此诊断不应自行扩成“三个胚胎组齐全才能提交”等新增门槛。

**2．motion 重连没有直接保留 ILP 的分裂拓扑。**

`SOURCE_CODE_VERIFIED`：每帧两轮一对一 Hungarian 匹配后，只要返回非空边，就用 `edges = motion_edges` 替换原 ILP 边容器；原学习概率仍通过成本奖励使用。因此不能称 ILP 完全无效，但学习得到的原分叉不能直接保留。`MEASURED`：B0 普通运行四个视频最终分裂父节点为 51/15/9/27，逐项等于 safe-div 新增数；被替换容器合计 118415 条边，这不是说 118415 条边的端点全部改变。[自有 B0 固定源码](https://github.com/SailorRen/Biohub-CELL/blob/175054cb891e2f7981d196a6c1cb6d26f8d6abcf/experiments/PUBLIC946_TTA_20260908/B0/candidate.ipynb)

应先记录 ILP→motion→gap→safe-div 各阶段的真实分裂事件保留/丢失，而不是直接增大分裂半径或取消运动重连。若确有高可信正确分裂被覆盖，再单独试验“保留这些分叉，只在剩余节点上重连”。需要保持相邻帧、每女儿唯一父节点、每父节点最多两个女儿；增加分裂数本身不是成功。上述收益为 `INFERENCE / NOT_RUN`。

## 建议下一轮按这个顺序优化

| 顺序 | 具体工作 | 为什么做、何时停止 | 当前状态 |
|---|---|---|---|
| P0 诊断 | 固定官方 scorer，核对相同预测；记录候选可达性、同母排序、门限拒绝与后处理保留 | 找到损失发生阶段；不把旧 proxy 的 TP/FP/FN 当官方真值 | NOT_RUN |
| P1 小候选 | **仅让 linefit 平滑在分裂边界停止**，保留 B0 weight=.8、window=2、全部模型和原自动 PP | 当前女儿回溯可以跨过分叉父节点，可能混合分裂前后运动；这是源码行为，尚无伤害或收益实测 | NOT_RUN |
| P1 后续独立候选 | 有逐事件证据后，再试可靠 ILP 分叉保留 | 改动比平滑边界大；若原分叉主要是错分裂，则放弃该方向，不强行保留 | NOT_RUN |
| P2 检测定位 | 保持峰数量/NMS/阈值，单独评估真实检测峰的亚网格坐标细化 | 当前有效输出步长约1.625µm；末端平滑可能覆盖收益，需分阶段看定位与匹配 | NOT_RUN |
| P3 新信息 | 不同邻帧窗口聚合；或许可和谱系清楚的外部数据、FOCUS伪标签蒸馏及较长时序关联 | 引入当前系统没有的上下文/训练信息；开发与计算成本高，需要独立任务预算 | NOT_RUN |

P1 的两个候选相互独立，不组合提交。若希望先做一个范围最小的候选，我建议先测**分裂边界内的 linefit**。最小验证应覆盖直线轨道保持不变、父/两女儿分叉、轨迹起终点，并记录受影响节点数与位移；随后用自己的精确 Notebook Version 与正式 submission 对照 B0。原跨边界平滑也可能有利，因此不承诺提分；没有正式提高就保留 B0，不继续扫描窗口或权重。

检测细化需保持浮点坐标和边特征采样一致。合成 gap 节点已有原图强度质心精修，不能把那部分当新功能。当前 `seen_frames` 保留同一帧首次窗口检测，后续关联使用当前窗口特征，研究不同邻帧上下文比简单重复同两帧更有依据。仅反转两帧再逆回的 encoder TTA 低优先级：当前共享空间卷积与时间 attention 没有时间位置编码或 causal mask，数学结构对排列等变；这是源码推导，未做数值等变测试。已有反向 edge-head harmonic 是另一条路径，不应混为一谈。

## 讨论区和 GitHub 对这些选择提供了什么证据

[CV 与 LB 差异讨论](https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/739685)和[本地 CV 讨论](https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/739352)中，参与者报告本地改善远大于榜分变化，建议拆开节点、连接与分裂指标。这些是 `COMMUNITY_REPORT`，没有绑定可复算 submission，不能据此认定本项目过拟合或测试分布偏移。帖子里的短 gap 频率例子也不是测量数据。

[删节点负面案例](https://www.kaggle.com/code/zhincez/the-metric-pays-you-to-delete-nodes) V4 自述 proxy 0.9368→0.9495、LB 0.938→0.934，属于 `AUTHOR_CLAIM`，没有正式 submission 绑定。其代码用绝对变化比估算贡献，不是 `J×数量乘子` 的精确归因，不宜照抄。稀疏 GT 下，B0 的183084个“未匹配预测节点”不能全部称为假阳性；旧诊断错连接数0也不证明没有错误。应避免为改善节点数量项而普遍删轨。

[FOCUS 讨论](https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/738217)提出密集伪标签→快检测器蒸馏→位置校准和更长时间窗链接；[候选精修讨论](https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/740145)建议对高召回短名单做更强上下文重排。作者的召回数值不是本项目独立正式成绩，部分还排除分裂。本轮没有审读图像内测量。直接 FOCUS 推理的超时反馈说明还需考虑推理预算，不能把大模型接入当简单替换。

GitHub 核心源码核验给出以下限制和可借鉴部分：

- [HOCT 固定版本](https://github.com/royerlab/hoct/blob/2ccc5040823bc944ab67790abd1f56eea7cd4f05/src/hoct/_api.py)：支持5帧上下文、orphan 概率和 tracklet ILP，但 `create_graph_from_points` 只有 TODO/pass。需实例标签或完整 regionprops；默认允许跨时间边的结果还需适配本赛相邻帧规则。T4/BF16兼容、训练谱系和耗时未核验，不能直接替换 B0 点集关联。
- [Trackastra](https://github.com/weigertlab/trackastra/blob/aa57a95160002e0fc70b915ab74178b39c99fd6a/trackastra/model/predict.py)：可借鉴多窗口预测汇总；单纯移植 ILP 名称没有价值，因为 B0 已有图优化。
- [matt-ceran 的真实候选排序诊断](https://github.com/matt-ceran/biohub-cell-tracking/blob/446589b772f4d98adecc3f6ba15434f0e0d57069/src/biohub/division_truth_rank.py)：可借鉴“候选是否存在→排序→门限→分配冲突”的拆解。其 metric 是近似实现且未发现 LICENSE，不能替代官方 scorer 或直接搬代码。
- [FOCUS-3D 接口](https://github.com/yu-lab-vt/FOCUS-3D/blob/5c4b53f743a0fbbae056e2c1a139895ae819f069/src/focus3d/segmentation/mask2former_adapter.py)：当前 adapter 使用 no-Detectron2 路径，模型 core 未深读；权重访问有条件，本轮未申请或下载。适合独立检测支线研究，不构成已获本赛收益。

[主办方回复](https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/734330) comment3512606 明确允许 Zebrahub 数据与资源，并称无测试重叠；浏览器已核验作者 COMPETITION HOST 身份，分类 `HOST_CONFIRMED`。具体外部资产仍需逐版本核验谱系与许可，本轮没有新建数据或训练。相比从零构造复杂合成器，先研究真实允许的数据更有依据；合成数据无收益的参与者反馈也不是普遍否定模拟的方法。
